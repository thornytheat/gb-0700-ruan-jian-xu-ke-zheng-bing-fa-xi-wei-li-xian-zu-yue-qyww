# 席位定义

lease_id、user保持字符串。CAD-Pro、cad归一为CAD。kind取online、offline、heartbeat、release、capacity。start/end必须带时区并转换UTC。seats为正整数；capacity记录表示采购生效区间的席位上限。

在线租约可由同租约同版本release提前结束；离线授权一直占用至原到期时刻，即使收到release仍保留。心跳不建立租约。租约采用最高版本；同版多条实体租约冲突隔离。采购区间可重叠，最高version优先，同最高版不同数量返回CAPACITY_CONFLICT。

并发使用半开区间[a,b)，结束同刻开始不重叠。采购边界必须切分并发段。超用责任按租约开始时间倒序、再按编号倒序分配，分配席位严格等于超用数量。超用席位小时为超用数量×秒数/3600，Decimal计算。此工具只核验约定席位数，不含厂商复杂许可证条款。

租约ID在产品内唯一；不同产品允许相同租约号。线上租约在start同刻release得到零时占用，离线仍保留原到期。

# 容量分界（M8）

- 生效时刻（anchor）：某产品有效采购容量发生变化的时刻（容量区间开始/结束、下调、恢复、再次修订）。每个生效时刻开启一个容量世代。
- 受保护旧租约（protected）：在生效时刻之前已开始、且在该时刻之后仍占席的租约。离线租约始终保护到原到期，即使收到 release；在线旧租约保护到自己的结束时刻。受保护旧租约不追溯判超用。
- 剩余容量（remaining）：`max(0, 容量 - 受保护占席)`。
- 新占用（new）：在生效时刻及之后开始的租约。新超用 `new_excess = max(0, 新占用 - 剩余容量)`，责任只在新的租约之间按开始时间倒序、编号倒序分配。
- 旧租约占超（protected_over）：`max(0, 受保护占席 - 容量)`，说明缺口来自历史承诺，不向旧租约追责。恒等式：`protected_over + new_excess = max(0, 总并发 - 容量)`。
- 世代状态：`PASS` 余量充足、`PROTECTED` 仅受保护旧租约、`OVERUSE` 新占用越过剩余容量、`CAPACITY_CONFLICT` 同最高版容量数量冲突。

发布与修订：

- 同一系列（同一批租约编号与产品）只保留一条已发布结论；系列内容量每次有效修订形成新版本。
- 结论指纹相同视为同一修订重跑：不新增版本、不重复扣减，返回已发布结论。
- 修订时按两版区间端点并集切分，只重算内容变化的子区间；未变化区间标记 `carried` 并记录 `source_revision`，删除区间进入 `merge.removed_*`。
- 发布失败或中断时整体回滚，保留上一版完整结论、原始依据与受保护旧租约记录；失败尝试只追加到发布尝试表。
- 后续修订不再出现的受保护旧租约转入 `retained_protected` 保留档案，证据导出标记 `RETAINED`。
